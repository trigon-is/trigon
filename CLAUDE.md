# Trigon — notes for Claude Code

Trigon is a bash + Docker Compose harness that runs one coding agent (Claude Code,
OpenCode) against one LLM provider in one toolset mode per container run. There is
no internal orchestration; pipelines are built outside it. User-facing overview:
`README.md`. Architecture: `docs/trigon-architecture.md`.

## Start of a session

1. Read `docs/session-start.md` (project primer, "Current state" section) for where
   work left off.
2. If on a feature branch run as an AI-DLC cycle, read its state file — currently
   `docs/audit/aidlc-state.md` for the M7 `--audit` feature on `feature/audit-inception`.
3. This repo may be mounted somewhere other than `/app` (e.g. `/app_4` from a
   multi-project session). Use absolute paths; the shell cwd may reset to `/app`.

## Layout

- `trigon-up.sh` — the launcher: arg parsing, guards, compose assembly, launch.
  Organised by `# ── Section ──` banners; keep that style.
- `build.sh` — builds `<agent>-<mode>:latest` images and the audit gateway image.
- `compose/base.yml` — the agent service (`trigon`); everything else is layered as
  compose fragments. Static ones live in `compose/`; per-run ones are generated by
  `trigon-up.sh` via `mktemp_yml`, registered in `TEMP_FILES`, removed by `cleanup`.
- `agents/<name>/` — Dockerfile + `wrapper.sh` per agent. `modes/<name>/` — package
  lists per mode. `providers/*.yml` — provider definitions (schema: `providers/schema.md`).
- `lib/*.py` — stdlib-only host helpers (provider parsing, MCP merge, audit summary).
- `docs/` — guides (`providers.md`, `agents.md`, `modes.md`, `mcp.md`), the threat
  model, AI-DLC artifacts (`docs/audit/`, rules in `docs/aidlc/`). `docs/internal/`
  holds strategy notes, not user docs.

## What needs a rebuild

Changes to `trigon-up.sh`, `compose/*.yml`, `providers/*.yml` or `lib/` take effect on
the next launch — no image rebuild. Changes to `agents/*/Dockerfile`, `wrapper.sh`,
`modes/*` or `compose/audit/` (gateway image) need `./build.sh ...`. A running
session never picks up launcher changes; it needs a relaunch.

## Checks (no Docker needed)

```bash
shellcheck trigon-up.sh build.sh agents/*/wrapper.sh
for f in trigon-up.sh build.sh agents/*/wrapper.sh; do bash -n "$f"; done
python3 -m py_compile lib/*.py
python3 -m unittest discover -s tests
bats tests/cli
```

Inside a Trigon container `bats` and `shellcheck` may be missing; `bats` can be
cloned from github.com/bats-core/bats-core into a scratch dir and run from there.
Say which checks were skipped. Real-container behaviour (images, providers,
Playwright, `--audit`) can't be verified without Docker on the host — say so
rather than claiming it works.

New flag or guard → add a case in `tests/cli/*.bats` (use `--dry-run`, which prints
the compose command and exits before any container starts). New provider → case in
`tests/test_parse_provider.py`.

## Conventions

- `#!/usr/bin/env bash`, `set -euo pipefail`, quote expansions, `[[ ]]`.
- Portability: Linux is reference, but macOS bash 3.2 / BSD userland must work
  (no `mapfile`, no GNU-only flags; see `mktemp_yml`).
- Anything written into a mounted project (e.g. `.mcp.json`) is restored or removed
  by the `cleanup` trap.
- Security first: read `docs/threat-model.md` before touching mounts, capabilities,
  networking or `/settings`. Cite the goal (G1–G9) in comments, as existing code does.
  Never weaken a guard silently; overrides are explicit flags (`--allow-unsafe-mount`,
  `--allow-metadata`).
- `--audit` must fail closed: never run unaudited when auditing was requested.
- Commit messages explain the why. Don't push or open PRs unless asked.

## AI-DLC cycles

Feature work may run as a full-ceremony AI-DLC cycle (rules in `docs/aidlc/`).
In that case: keep `aidlc-state.md` current, append every interaction to the cycle's
`audit.md` (user input verbatim, append-only), and stop at the approval gates.
Small fixes outside a cycle don't need the ceremony.
